## §1 写作风格与章节模板（通用规则，保留）

> 全部提炼自作者手稿，与具体作品无关。适用范围：**所有章**。

### 1.1 章节结构模板

```
开篇（肉体体感）→ 行动 → 交互（对话）→ 内心推演 → 时间流转 → 结尾（实体钩子）
```

### 1.2 语言与排版约束

| 项 | 约束 |
|---|---|
| 逗号:句号 | ≤ **2.8**（逗号串联保留，但每 2–3 个逗号必落句号） |
| 句长 | 25–40 字；禁电报体（连续 ≥3 个短于 8 字的碎句） |
| 段落 | 无小标题/编号/加粗/分隔线；单段 ≤ 200 字；全章 18–25 段 |
| 对话 | 精简，符合人物身份；不自报家门式介绍 |
| 比喻 | 白描为主，全章至多一处，不叠比喻 |
| 感叹号 | 全章 ≤ 1 个 |
| 视角 | 第三人称贴主角，全章 1 个视角，不写他人内心 |
| 禁 AI 痕迹词 | 不禁 / 竟然 / 不可思议 / 值得一提的是 / 事实上 / 众所周知 / 缓缓 / 微微（连用） |

### 1.3 感受的写法

直写体感，不写"他感到 / 他觉得 / 他心中涌起"。

```
✅ 压抑的喘不过气来，绝望的感觉浸染身心。
❌ 他感到一阵压抑，绝望的情绪涌上心头。
```

### 1.4 人物行为模式

**多想少说**：内心活动丰富，口头表达克制；用微表情（脸皮抽动、淡笑、眼神漠然）传情绪，禁大段说教。

### 1.5 悬念与结尾模式

- 靠**细微暗流异变**推进，拒绝爆炸式冲突与爽文浮夸。
- 修炼 = 水磨功夫，**禁**无铺垫的修为暴涨 / 开挂。
- 章节结尾必须留**可感知的未决点**，二选一：
  - 现实向：修为瓶颈 / 势力疑点 / 未了结事件
  - 异象向：藤蔓、大阵、未知窥视出现一丝细微新异动
- ❌ 禁止纯情绪感慨收尾。

### 1.6 信息约束

不要一次性抛出全部世界观谜底；角色说出的情报要**拆分**，部分疑问留给主角，维持悬念。

### 1.7 时间跳转

短时段用生理状态过渡；大跳转（数月/一年）补一小段小结交代状态变化。

## §3 真实 MCP 工具与完整工作流

### 3.1 真实工具清单（仅此 6 个）

| 工具 | 参数 | 作用 | 读写 |
|---|---|---|---|
| `funnel` | — | 读 `05_管线框架/funnel.yaml`，报 L0–L5 哪层没 done | 只读 |
| `ne_db` | — | 真值库状态（表/行数/卡用量 top） | 只读 |
| `ne_db_query` | `sql`, `limit` | 执行只读 SQL（`SELECT`/`PRAGMA`/`EXPLAIN`） | **只读**，写操作直接拒绝 |
| `ne_inject` | `volume`, `chapter`, `allow_missing` | 取本章**注入包**（角色/资料卡/前文/伏笔/事件/缺失引用）+ `chapter_plan` | 只读 |
| `ne_cardgen` | `volume` | 从卷细纲抽【待建卡】工单，按类别归堆 | 只读 |
| `ne_check` | `text`, `chapter`, `volume` | 跑 16 道门禁，返回 verdict + P0/P1 清单 | 只读（校验文本，不落库） |

### 3.2 工作流（严格按序）

```
1. funnel            → 看当前推进到哪层（L0–L5）
2. ne_db             → 确认真值库可读
3. ne_inject(vol,ch) → 取本章注入包 + chapter_plan（⚠ 剧情/人物状态的唯一来源）
4. ne_cardgen(vol)   → 若本章需建新卡，拿待建卡工单
5. （写正文：注入包 + §1 全部风格铁律）
6. ne_check(text,…)  → 16 门禁自检，拿 verdict
7. verdict≠pass → 按 P0/P1 修改 → 重跑 ne_check，直到 pass
8. 交稿（§4 格式）
```

### 3.3 章节缺口处理（重要，勿踩坑）

**不能**简单 `max(chapter_no)+1`。`ne_inject` 返回的 `chapter_plan` 已内置缺口识别：

```json
{
  "generated_chapters": [1, 3],
  "has_gap": true,
  "first_gap": 2,
  "suggest_fill_gap": 2,
  "suggest_append": 4,
  "default_target": 2,
  "note": "检测到第2章缺失，默认优先补缺口（mode=fill_gap）；如需跳过缺口向后续写请显式传 chapter=4"
}
```

两种模式：

| 模式 | 何时用 | 取号 |
|---|---|---|
| **补缺口**（默认） | 有编号缺口时 | `suggest_fill_gap` |
| **向后续写** | 缺口是有意跳过时 | `suggest_append`，且**须显式传 chapter** |

> 当前实测：卷01 已有第1、3章 → **默认写第2章**，不要直接写第4章。

### 3.4 交付契约（明确边界）

- AI **只输出文本提案**；AI **没有写库权限**（`ne_db_query` 拒绝 INSERT/UPDATE/DELETE/DROP）。
- 全部内容须经 `ne_check` 闸门校验。
- 落库由人工/CLI 执行（当前无自动入库 MCP 工具）。
- **不要把整本小说塞进提示窗口** —— 人物、伏笔、状态全靠 `ne_inject` 动态拉取，防上下文爆炸。

## §5 交稿前自检清单

1. 是否存在大段未换行的密集文本？
2. 开篇是否带入人物**肉体感官**体验？
3. 陈寂是否做到**想得多、说得少**，内心想法与口头言行存在区分？
4. 结尾是否设置**实体钩子**，而非单纯情绪收尾？
5. 是否发生 OOC、凭空新增重大设定、重要人物？
6. 是否一次性把大量世界观秘密全部揭露？
7. 是否出现爽文浮夸表达、无铺垫强行升级开挂？
8. **是否出现 张木/刘老/幽山宗 等非本书人名？出现即重写。**
