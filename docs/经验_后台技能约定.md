# 经验：后台技能运行约定（2026-10-14 确立）

## 为什么要后台跑

Rust release 编译 + 全量测试（~270 个 test）单次耗时数分钟。若前台阻塞等待，
大量时间空转。故：**编译/测试/提交全部后台，前台继续写代码/思考/总结**。

## 三个技能

| 技能 | 命令 | 输出 |
|---|---|---|
| 编译+测试 | `nohup ./tools/skill_ci.sh <stage> &` | `.ci/<stage>.log` |
| 提交 | `./tools/skill_commit.sh "msg" <stage>` | `.ci/commit_<stage>.log` |
| 轮询 | `tail .ci/<stage>.log` | 末行 `RESULT=...` |

## 日志末行契约（稳定，便于程序判断）

```
RESULT=OK passed=502 failed=0        ← 可提交
RESULT=TEST_FAIL passed=267 failed=1 ← 拒绝提交
RESULT=BUILD_FAIL errors=3           ← 拒绝提交
RESULT=COMMITTED hash=abc1234 rc=0
RESULT=COMMIT_SKIP reason=ci_not_ok
```

`skill_commit.sh` 会在提交前检查 CI 末行，非 `RESULT=OK*` 直接拒绝。

## 踩过的坑

1. **CI 脚本最初把 `failed>0` 也报 OK** —— 因为 `passed=261 failed=7` 时
   末行仍是 `RESULT=OK`。已修：现在 `failed≠0` 或 `passed=0` → `RESULT=TEST_FAIL`。
   **教训**：门禁脚本自身必须有反向用例（故意失败也必须拒绝）。

2. **测试夹具缺表** —— 记忆子系统读既有库表 `char_state`，但内存库只建了新 schema →
   7 个测试 panic `no such table: char_state`。已在 `fresh()` 补最小桩表。
   **教训**：跨模块读既有库表时，测试夹具要显式建桩，别指望它存在。

3. **release 测试比 debug 慢，但更接近交付** —— 统一用 `--release`。

## 前台在等 CI 时该做什么

- 写/更新交付文档（`docs/*.md`）
- 核对数据（`sqlite3` 查询、文件对比、prompt 组装校验）
- 写下一个 stage 的代码
- 总结经验（本文件）
- **不要**重复跑前台 `cargo build`（会和后台 CI 抢编译锁）
