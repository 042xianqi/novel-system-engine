## 一、仓库总览

```
小说系统/                      # 残响之河 novel-engine（纯 Rust）
├── Cargo.toml                 # workspace 根：9 个 member crate
├── Cargo.lock
├── README.md                  # 入口：crate 分工 + 模块↔Python 对照 + 上游缺陷修复
├── PROGRESS.md                # 资料库数据层重构的进度存档（续跑必读）
├── .gitignore                 # target/ 与 *.bak
│
├── crates/                    # ← 全部 Rust 源码（见 §二）
├── docs/                      # ← 规范、ADR、SQL（见 §三）
├── tools/                     # 空目录，预留给离线运维脚本
└── target/                    # cargo 产物（不入库）
```

**为什么不是单 crate**：这条管线有 9 个关注点（数据模型 / 漏斗 / DB / 注入 / 引擎 / 质检 / 建卡 / 导入 / MCP），
生命周期与依赖方向都不同（如 `ne-import` 是一次性工具，`ne-engine` 是常驻主体）。
单 crate 会让"改一处、全量重编"成为常态。

另外：

- **全盘搜索重编号后的文件名（`*｜*`）命中 0** —— `CODE｜名称.md` 形态的文件不存在于任何位置，
  **说明"改名"那一步从未落盘**（`renumber_map` 只生成了映射，没执行）。
- `materials.file_path`（959 行）三处对不完：live 命中 **0**，冷备份 **567**，trash **518**。
  逐行判定后分成三堆（见下表）。

| 堆 | 行数 | 含义 |
|---|---|---|
| ① 磁盘可定位 | **575** | file_path 在 live / 冷备份 / trash 之一真实存在 |
| ② 磁盘无、DB 有正文 | **365** | 文件找不到，但 `materials.content` 里正文完整 |
| ③ 磁盘无、DB 也无正文 | **19** | 删除候选（18 蓝星篇 + ORG-99-012） |

**结论**：`s10 删源审查`的真正风险**不是"内容没导全"**——② 的 365 行正文 100% 已在库中。
风险只在**反向**：磁盘上是否还有 DB 缺失的内容。故放行前应：
① 对冷备份 818 个文件做 SHA 全量比对，产出"磁盘有、DB 无"清单；
② 补上 §四 那 8 张漏导；③ 拍板 19 张删除候选去留。
