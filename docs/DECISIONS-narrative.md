# 叙事层落地方案（ADR）

> 2026-10-10 立项。基于**全量实读**（818 张卡 / 626 有结构；40 张表实测 schema；
> 1800 章细纲；Rust 源码）后作出的决策。**不是提案，是待执行计划。**

---

## 一、背景：三类已核实的问题

### 🔴 F1 `ne-db` schema 与真库不符 —— 查询路径是死的

```
ne-db 声明:  foreshadow(fs_id, plant_chapter, ...)
真库实际:    foreshadow(id, planted_volume, planted_chapter, deadline_volume, deadline_chapter, ...)

实测:  SELECT fs_id FROM foreshadow  →  ❌ no such column: fs_id
       INSERT INTO chapters(chapter) →  ❌ no such column: chapter
       timeline(moment)              →  ❌ 同
```
`ne-db::SCHEMA` 建的是另一套表，与真库的 6 张业务表**对不上**。
→ **后果**：任何经 `ne-db` 的写入路径在真库上直接失败；查询也只能绕过。

### 🔴 F2 1800 章细纲是机械模板生成 —— "AI 味"源头

```
卷01.md:  180 章 = 36 个基标题 × 5 个固定后缀
  ### 第1章 涧底醒
  ### 第2章 涧底醒·阻碍具象
  ### 第3章 涧底醒·选择挣扎
  ### 第4章 涧底醒·代价体感
  ### 第5章 涧底醒·钩子        ← 同一"点位"机械拆成 5 章
```
10 卷**全部都是 180 章**，每章概要字数却从 230 到 1058 字不等。
→ **这正是用户指出的**："一样的章数不就相当于告诉他们是 AI 写的吗"。

### 🔴 F3 卷章数硬编码 —— 与"按实际伸缩"直接冲突

| 位置 | 内容 | 问题 |
|---|---|---|
| `ne-engine/src/loaders.rs:288` | `heads.len() == 180` | **硬断言**，卷章数必须 180，否则报错 |
| `ne-engine/src/loaders.rs:208` | `seg_no = (ch - vol_start) / 60 + 1` | 硬编码 60 |
| `dynamics_config.json` | `volume_beat.chapters_per_volume = 18` | 与实际的 180 **自相矛盾** |

→ 三套口径打架。**要"按实际写"，这三处必须先解开。**

## 二、决定

### 决策 1：分层编号 —— **保留现役 L0–L5，不重构**

| 层 | 现役含义（funnel.yaml） | 用户新提案 | 处置 |
|---|---|---|---|
| L0 | 整本概括 | 世界观总纲 | 保留现役；世界观总纲归入 **L4 资料库**（它本就是世界观卡） |
| L1 | 具体总纲 | 全书主线 | 保留现役 |
| L1x | 宏大对抗总规划 | — | 保留 |
| L2 | 分卷大纲 | 分卷大纲 | ✅ 一致 |
| L3 | 细纲 | 卷内细纲 | ✅ 一致（用户新增"块节点"作为 L3 的子结构） |
| L4 | 资料库 | 单章要点 | 保留现役；**单章要点另起 `L3.5`** |
| L5 | 正文 | — | 保留 |

**理由**：1800 章细纲、`funnel.yaml`、16 门禁、`ne-core` 解析器**全部依赖现役编号**。
改编号 = 全链路返工。用户的新语义**可作为子层挂载**，无需推翻。
**代价**：编号读起来不如用户原提案直观 —— 接受，因为收益（零返工）远大于此。

### 决策 2：新增表必须**同构于现有 `*_state` 投影体系**

现有 `*_state` 表的关键约定（**已实测确认**）：

```sql
code TEXT,         -- 编号 LOC-99-001，与 materials.code 对齐（实测 38/38 匹配）
source_card TEXT,  -- 源 Markdown 路径 02_资料库/地图/LOC-99-001.md
source_sha TEXT,   -- 源文件指纹，防漂移
basis TEXT,        -- '实值' | '推测' | '待核'
```

**所有新增表一律带上这 4 列。**
**理由**：避免再造"第二套投影"，重演 F1 那类 schema 分裂。
**代价**：字段略冗余 —— 接受，一致性优先。

### 决策 3：概念重叠的表 —— **加列，不新建**

| 用户模板 | 现有表 | 处置 |
|---|---|---|
| J 地点 | `map_state`(38) | **加列**：表层传说 / 深层秘密 / 进入代价 / 伏笔锚点 |
| K 奇物 | `treasure_state`(11) | **加列**：代价三档 / 流转历史 / 认知分层 / 禁则 |
| L 历史事件 | `events`(46) | **加列**：多版本流传 / 认知分层 / 深层根源 |
| V 力量体系 | `power_state`(24) | **加列**：异化倾向 / 天花板 / 登顶者 / 体系盲区 |
| W 世界异常 | `anomaly_state`(14) | **加列**：假说分层 / 安全阈值 |
| G/U 坑与伏笔 | `foreshadow`(12) | **加列**：放出强度 / 弱提示计数 |

**理由**：这些表**已有真实数据且是派生投影**，新建会分裂。
**注**：现有表**已有** `deadline_volume/deadline_chapter`（计划回收区间）——
早先"foreshadow 没有回收区间"的说法**有误**，此处更正。

### 决策 4：真空白的表 —— 分批新建（不一次 30 张）

**A 批（优先，8 张）** —— 补最痛的空白，服务演算引擎：
`plot_block` · `chapter_beat` · `character_core` · `pending_setting` ·
`foreshadow_hint` · `plot_theme` · `world_snapshot` · `author_log`

**B 批（次优，8 张）** —— 写到 300 万字后才用得上：
`char_relation` · `ideology` · `choice_case` · `lie_chain` ·
`info_flow` · `mental_domain` · `comm_link` · `entity_mark`

**C 批（延后）** —— 政策/自由变量等长尾：
`free_var` · `conflict_plan`(并入 dynamics_events) · `comm_scene`

### 决策 5：字数/卷 —— **按实际伸缩**，废除硬编码

- 删 `loaders.rs:288` 的 `== 180` 断言，改为「按实际章数解析」
- `seg_no` 的除数 60 改为**读配置**（默认 60，可覆盖）
- `dynamics_config.json` 的 `chapters_per_volume=18` 与实际的 180 冲突
  → **统一以「细纲实际章数为准」**，配置只作建议值
- **不强制每卷等长**：允许 120/150/200/260 章

### 决策 6：静:动 节奏口径 —— **按章数，不按字数**

用户规范提"静:动 ≈ 55:45"。**按字数会失真**（一章静 8000 字能压掉五章动）。
→ 采用**章数占比**，与 `rhythm.flat_chapter_cap` 的口径一致。

## 五、明确不做（及原因）

| 不做 | 原因 |
|---|---|
| 把 L0–L5 重构为用户的新编号 | 全链路返工（细纲/门禁/解析器），收益不成比例 |
| 一次建 30 张表 | 会造出大量空表 + 第二套投影，重演 F1 |
| 引擎自动判定"是否符合 L0" | 需语义理解，确定性门禁做不到；只能查**引用合法性** |
| 强制每卷同章数 | 与用户明确要求冲突，且是 F2"AI 味"的成因 |
| 直接改真库的表结构 | 需先备份（WAL 三文件），且用户确认 |

## 六、给数据的安全约定

- **WAL 三文件**：`novel.db` / `novel.db-wal` / `novel.db-shm` —— **备份必须三个一起**
- 改现有表结构前必须备份
- 新增表用 `CREATE TABLE IF NOT EXISTS`，可重复执行
