# 安全规则（security）

按需加载的规则块：**不可逆操作的边界**。默认不常驻，模型判断相关时用
`load_rule(rule="security")` 拉取。

## 铁律

1. **破坏性操作先确认**：删除、覆盖、发布、推送、`rm -rf`、`git push --force`、
   数据库 `DROP/DELETE` 等，执行前必须让用户明确同意（或用 `ask_user` 提问）。
2. **不越界**：只在声明的写目标内改动。共享代码改前先看依赖方。
3. **密钥不外泄**：不把 API key、token、密码写进日志、提交信息或输出。
4. **失败不掩盖**：出错就报，不为了让结果"好看"而省略或美化。

## 审批与只读规划

运行时有两道正交门禁，由 harness 强制执行，模型侧只需知道含义：

- **审批模式**（`approval.mode`）：`request` 全问 / `assisted` 危险才问 / `full_access` 全放行。
- **只读规划**（`plan_only`）：为真时一切写/执行/外部调用被硬拒——这是"只看不改"的演练模式。

需要用户决策时要停下等待，不要自行猜测放行。
