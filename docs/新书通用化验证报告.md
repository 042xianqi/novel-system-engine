# 写一本新小说能用吗？—— 通用化改造与验证报告

> 结论先行：**改造前不能直接用于新书；改造后可以。**
> 本报告给出实证证据、改动清单、以及新书开写流程。

## 一、你问的问题

> 「假设我写一本新小说，用这个系统能正常用吗？」

之前的回答不成立，因为**所有测试都在《残响之河》已有库上做**。
这次真建了一本空白新书库（主角「林知远」），从零跑了一遍，拿到实证答案。

## 二、实证：新书撞上了什么

### 实验设置
- 新建空白库 `/root/newbook`（8 张表）
- 写一段新书正文（主角「林知远」，与《残响之河》无关）
- 跑 `ne-engine check`（16 门禁）

### 改造前的失败（铁证）

```
G05_pov_consistent  ✗  陈寂0命中，视角锁定失守
  [G05] 正文无主角陈寂（技06 视角锁定：非陈寂视角章打回）
```

**新书主角「林知远」被《残响之河》的硬编码「陈寂」直接 P0 打回**——
这不是写作问题，是系统把书名/主角/家族/禁词**写死在 Rust 源码里**。

### 硬编码清单（改造前）

| `gates.rs:67` | 家庭 canon `陈大山/林氏/陈默/陈老头`（G15） |

涉及 **30 个源文件**、**两套并行的门禁实现**（`gates.rs` 与 `gate14.rs`）。

## 三、改造方案：书档案（BookProfile）

**核心原则：默认值 = 历史硬编码**，所以《残响之河》行为逐字不变；
新书只要在库里放一个 `book_profile.json` 即可覆盖。

### 新增数据结构
`crates/ne-engine/src/config.rs` 新增 `BookProfile`：

```json
{
  "title": "星尘渡口",              // 书名（system prompt）
  "protagonist": "林知远",          // 主角名（G01/G05）
  "novel_id": "xingchen",           // 写库 ID（原 'canxiang'）
  "horror_keywords": ["异象","低语"],// G10
  "ability_keywords": ["星纹"],      // G04
  "cost_keywords": ["代价","失去"],  // G04
  "g01_b": ["星纹","渡口"],          // 开篇·金手指
  "g01_c": ["星蚀","宿命"],          // 开篇·核心矛盾
  "g01_d": ["前世","这具身体"],      // 开篇·身份交代
  "canon_family": [["父亲","林崇山"]],// G15
  "canon_names": ["林崇山","苏晚"],
  "myth_banned": ["星神本源"],       // G14
  "banned_words": ["灵气","丹田"]    // 正典禁词
}
```

加载优先级：`book_profile.json` ＞ `dynamics_config.json` 的 `book_profile` 键 ＞ 历史常量。

### 改动清单

| 文件 | 改动 |
|---|---|
| `config.rs` | +`BookProfile` 结构 + 访问器（None→回落历史常量）；`load()` 合并书档案 |
| `gates.rs` | G01/G04/G05/G10/G13/G14/G15 改读 `cfg.book_profile`；提示文案去泄漏 |
| `gate14.rs` | 同上 7 门（第二套实现），`GateCfg` 增 `book_profile` |
| `chapter.rs` | +`deterministic_check_with(banned_words)`（旧签名保留兼容） |
| `task.rs` | system prompt 用 `book_profile.title()` |
| `wire.rs` | `dynamics_events.novel_id` 用 `book_profile.novel_id()` |
| `gates.rs`（常量） | +`BOOK_TITLE_DEFAULT` / `PROTAGONIST_DEFAULT` |

### 新增工具
- `tools/newbook/export_schema.py` —— 从真库导出 60 表通用 schema
- `tools/newbook/init_newbook.py` —— 一条命令建新书库 + 书档案

## 五、现在怎么用（新书开写流程）

```bash
# 1. 建库
python3 tools/newbook/init_newbook.py /path/to/新书 --title '书名' --protagonist '主角名'

# 2. 填书档案（关键！）
#    编辑 /path/to/新书/05_管线框架/data/book_profile.json
#    —— 主角名、禁词、金手指词、家族 canon、novel_id 全部改成本书设定

# 3. 写细纲
#    /path/to/新书/03_叙事规划/细纲/卷01.md

# 4. 跑门禁验证
./target/release/ne-engine check --root /path/to/新书 --text 第1章.md --chapter 1 --volume 卷01
```

## 六、仍存在的边界（如实说明）

| 项 | 状态 |
|---|---|
| 门禁/注入/情绪/动力学 | ✅ 已通用化 |
| **主角情绪标定** | ⚠️ 新书需自行提供 `char_calib` 数据（否则按初值递推） |
| 社交网络 3 模型 | ⚠️ 需库里有 `adjacency` 邻接数据，新书暂无 |
| G13 的 63/67 维 | ⚠️ 仍需 LLM 离线评分（独立命令，非每章门禁） |
| `kb_rules` 表 | ⚠️ 不存在，写法规则块优雅降级为空 |
| 库规模（角色/地点数） | ⚠️ 新书天然从 0 开始，G13 会如实提示「未达标」（不阻断） |

**一句话**：门禁与写作链路已不再是《残响之河》专属；
但「资料库的厚度」（卡数量、标定、邻接数据）需要新书自己积累，
这是数据问题，不是代码硬编码问题。
