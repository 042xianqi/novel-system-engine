## 〇、一句话定位

ne 引擎 = 《残响之河》整本书的**生产 + 治理 + 质检**工具链。三层关系：

- **ne-engine**（底层库）：门禁 gate14、LLM 适配、世界物理、段落/情感/审计 —— 纯实现，无 CLI 编排
- **ne-agent**（编排 CLI，`ne-agent`）：30 个顶层命令，覆盖生成/治理/审计/会话/任务
- **ne-mcp**（MCP 服务，`ne-mcp`）：把能力暴露给 AI（太墟/Operit），15 个工具
- 另有独立小 CLI：`ne-funnel`（漏斗进度）

**调用方式三选一**：① CLI `ne-agent <cmd>`；② MCP `ne-mcp`（AI 用）；③ 脚本（`/root/novel-system/tools/*.py`）。

## 一、正文生产线（L5）—— 生成 / 质检 / 修复 / 落库

| 命令 | 作用 | 关键参数 |
|:---|:---|:---|
| `ne-agent novel` | **生成一章正文**：细纲→注入包→模型→门禁 | `--chap-id N`（章号）`--volume 卷01` `--lib <资料库根>` `--json` |
| `ne-agent score` | LLM **深读质检**（按 l5_质检.md；按需跑，不进门禁、不烧常规额度） | `<正文文件>` |
| `ne-agent fix` | 按 l5_修复.md **定向修复**（读 findings + 原文，最小改动） | `<正文文件> <findings.json>` |
| `ne-engine check` | 16 门禁质检（G01–G16 确定性 + 六维 AI 味） | 同 ne_check |
| `ne-engine sync` | 正文落库回填（章节表/char_state/伏笔/事件/时间线） | — |

**L5 闭环链**：`ne_inject`(注入包) → 模型生成（风格模板 `05_管线框架/prompts/l5_正文.md`）→ `ne_check`(16门禁) → 有 P0/P1 走 `fix` → `sync` 落库。
**注意**：旧 `05_管线框架/l5.py` 依赖的 `kb_quotes` 表已不存在（旧 Python 引擎遗产），**不要用**；用现行 Rust 链（见 `/root/novel-system/tools/l5gen.py`）。

## 二、漏斗管线（L0→L5）

| 命令 | 作用 |
|:---|:---|
| `ne-funnel` / MCP `funnel` | 读 `05_管线框架/funnel.yaml`，报各层状态（done / pending）|
| `pipeline scan-auto` | AI 引导全库扫描（= scan-library 包装；默认只产探针清单，`--ai-run` 才真实语义扫描）|
| `pipeline world-analyze` | 世界观分析（= scan-library --semantic 别名；只产结构化报告）|

**六层**：L0 整本概括 → L1 具体总纲 → L1x 宏大对抗总规划 → L2 分卷大纲 → L4 资料 → L3 细纲 → L5 正文。
现行顺序（funnel.yaml executor）：`L0→L1→L1x→L2→L4→L3→L5`（L4 在 L3 前：细纲引用需先有卡）。

| 命令 | 作用 | 备注 |

## 四、世界观认知治理（world-gov）—— 独立外挂，语义默认关

| 命令 | 作用 | 是否调模型 |
|:---|:---|:---|
| `world-gov bootstrap` | 建立世界观法理基线（只存摘要指纹，不存原文） | 否 |
| `world-gov inspect-card --key X` | 单卡深度检视（默认产探针包） | `--semantic --real-semantic` 才调 |
| `world-gov trace --key X` | 法理溯源链（key←受约束于←上层←L0） | 否 |
| `world-gov scan-library` | 全库语义脏点扫描 | `--semantic`；`--slice N/M` 分批 |
| `world-gov check-outline` | 卷细纲法理评估（只出报告不改细纲） | `--semantic` |
| `world-gov queue` | 语义管线队列（**进程内存**，退出即清） | 否 |

**三重锁**（真实外呼三条件**全开**）：① 编译 feature `llm_integration` + ② 环境变量 `WOGOV_ALLOW_REAL_LLM=yes` + ③ `--real-semantic` 参数（MCP 场景为工具参数 `real_semantic`）。
缺一 → `GATE_LOCKED`/`REAL_SEMANTIC_LOCKED`，绝不外呼。**默认态 = 锁闭安全基线。**

## 十、关键约定与铁律（容易踩坑）

1. **CI 覆盖陷阱（P9.1）**：`cargo build --release`（无 feature）会覆盖整个 workspace（含 ne-mcp）→ 三重锁第一锁失效。跑真机前必须 `--features llm_integration`；`skill_ci.sh` 已在末尾自动恢复。
2. **CLI 参数写法**：`conflict list --status pending`（长选项），**不是** `status=pending`。
3. **inspect-card 双开关**：`--semantic --real-semantic` 缺一停在 `PROBE_READY`（不报错、不推理）。
4. **work-root / lib**：都指向资料库根（含 novel.db）。`--work-root` 直读真实库；`vault` 是隔离沙箱。
5. **主索引零污染铁律**：`library_index` 684 条，任何 AI 产出只进隔离表（conflict_records/rel_edge/sandbox_* 等），绝不动主表。
6. **AI 无执行权**：AI 只出证据/建议/观点；修改、删除、终审必须人工。pending 观点池只增不改。
7. **端点**：真实 LLM 走 `http://127.0.0.1:8788/v1`（workbuddy 代理，设备侧进程，沙箱内无法自举）；模型 `glm-5.3-flash`。
