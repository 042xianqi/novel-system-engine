# 全库编号规范 v3（重编方案）

> 2026-10-10 设计。取代 v2.0（`CHAR-分类-序号-名称`）。
> **动因**：v2.0 存在**前缀冲突**——实测同一前缀被多类共用：
> `TECH` = 功法/力量体系/科技；`ART` = 物品/装备/天材地宝；
> `CAS` = 伏笔/因果线；`ORG` 与 `CIV` 都指文明；另有 `YGEN`/`OTHER` 异常前缀。
>
> **目标**：每类前缀**唯一**；覆盖 20 类卡片 + 叙事层（L0–L4）+ 新增实体；可机器校验。

---

## 一、编号总格式

```
<前缀>-<纪元号>-<序号>[·<状态>][-<名称>]
```

| 段 | 规则 |
|---|---|
| 前缀 | **4 位大写**，全局唯一（见 §二、§三） |
| 纪元号 | **2 位**：`01`–`09` 太玄帝国 ｜ `10`–`19` 天启 ｜ `20`–`29` 星耀 ｜ `30`–`39` 星际商会 ｜ `40`–`49` 暗影王朝 ｜ `50`–`59` 混沌 ｜ `80`–`89` 蛮族 ｜ `90`–`99` 跨文明/终极 |
| 序号 | **3 位**，类内递增，`001` 起 |
| 状态后缀 | 可选：`·待补` / `·草稿` / `·废弃` / `·封存` |
| 名称 | 可选，人读用；**机器只认前缀+纪元+序号** |

**唯一性约束**：`(前缀, 纪元号, 序号)` 三元组全库唯一。

## 五、唯一性校验规则（可机器执行）

1. **前缀唯一**：任两个实体类型不得共用前缀（本表已保证）
2. **三元组唯一**：`(前缀, 纪元号, 序号)` 全库唯一
3. **引用有效**：正文中出现的引用（如 `[CHAR-99-001]`）必须指向**存在**的编号
4. **归属一致**：卡片的编号前缀必须与其所在目录的类别匹配

> 校验由 `ne-engine audit` 与新增的 `ne-engine renumber --check` 执行。

---

## 六、重编执行策略（关键：保住引用）

⚠ **本库卡内大量硬引用**（如 `详见 CHAR-99-001`）。重编必须**同批改写引用**，否则断链。

```
步骤 1  扫描全库，建「旧编号 → 新编号」映射表（含冲突消解）
步骤 2  用映射表重写**所有引用**（正文内 + DB 内）
步骤 3  重命名文件
步骤 4  校验：无断链、无重号、无孤儿引用
步骤 5  全量导入 DB（含 content 全文）
步骤 6  对账：源字数 == DB 字数（逐卡）
步骤 7  审查通过后才可删源
```

**回滚**：映射表与原文快照一并存档（`09_冷备份/renumber_<时间戳>/`）。
